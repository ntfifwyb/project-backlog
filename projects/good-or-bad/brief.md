# Good or Bad

## Summary *

A "classifier" where the human is the classifier, made as an Anki deck. Each card shows one image
(donuts, a salad, a hobby, an activity) and the person labels it **GOOD** or **BAD**.
Context does not matter: donuts are BAD, salad is GOOD, full stop. The point is for people
to learn what they're putting into their bodies, and the same idea applies beyond food, to
hobbies and other things.

## Problem *

People excuse choices with context ("donuts are good in context, for instance if you're
spending time with someone"). The app rejects that: each item is judged on its own, so
people learn what the thing itself does to them.

## Users and context

Personal for now: just the user. Used as an Anki deck (desktop and phone via Anki's own apps).

## Success criteria *

- [ ] The user reviews the deck on their phone daily for a week without friction.

## Scope *

### Must (MVP)

- An Anki deck: each card shows one photo; the user decides GOOD or BAD.
- Items cover food first, but also hobbies and other things.
- Labels ignore context: each item has one answer, not "it depends".
- The back of the card reveals the answer with a **long** why: everything that's bad (or good)
  about it, including side effects down the chain (donuts → sugar → acne, overweight,
  blood pressure rise).
- Claude generates the items and their answers in a Claude Code session (research a
  batch, write the cards into the repo); no API key, no runtime cost.
- Answers are as objective as possible: each item is researched and gets an absolute
  GOOD or BAD, no in-between. Rule of thumb from the user: if it is avoidable, it is
  generally bad. This includes medicine (e.g. paracetamol: good or bad?).
- Medicine explanations add a safety line: when it's needed, and never stop prescribed
  medicine.
- The user approves each generated item in the repo files before the deck is built.
- Plain flip cards: photo front; back with GOOD/BAD, explanation, sources.
- Photos from free, openly licensed libraries (Unsplash, Wikimedia), with attribution.
- Progress, sync and export/import come from Anki itself (AnkiWeb sync, `.apkg`).
- First version: about 50 items.

### Later

- Possibly open it to the public (would need a policy recheck: privacy, minors, accuracy
  review).

### Not doing

- Context-dependent answers ("good if you're with friends").
- AI-generated images.
- A custom web app (replaced by the Anki deck, 2026-11-12).
- Its own accounts, server or progress storage: Anki handles that.

## Constraints

- Anthropic Usage Policy verdict (read 2026-11-12, AUP effective 2026-11-12): **allowed
  with limits**. Generic wellness/education content is excluded from the high-risk medical
  requirements, as long as labels aren't applied to the individual's own conditions,
  symptoms or medications. Limits: health claims must be accurate (no health
  misinformation); no body-weight or body-shape framing and nothing that encourages
  restriction, purging or compensatory exercise; if Claude talks to users, disclose it's
  AI; any stored per-user labels are health data (consent, clear data policy). Recheck if
  the app personalizes by health condition, is aimed at minors, or goes public. Accuracy
  still matters for a personal tool, especially for medicine: explanations name health
  effects such as weight gain as facts, never as judgements of people's bodies.

## Decided

- The human does the labelling; the app has a fixed GOOD/BAD answer per item, independent
  of context, with no in-between.
- Format: an Anki deck in its own repo, `good-or-bad` (not inside `anki-setup`), under
  the user's upcoming Anki organization.
- Audience: personal, just the user (for now). Was "public" in round 1; changed 2026-11-12.
- Items and answers: generated by Claude, researched per item, approved by the user.
- Images: openly licensed photos, never AI-generated.
- Generation: in Claude Code sessions, not via the API from an app.
- First version: about 50 items.

- [x] Web app or Anki deck? → Anki deck.
- [x] Own repo or inside anki-setup? → Own repo, `good-or-bad`.
- [x] How does Claude generate items? → In a Claude Code session.
- [x] First version size? → About 50 items.
- [x] Where are items approved? → In the repo files: the user reads or edits the card
  files before the deck is built.
- [x] Card style? → Plain flip card: photo on the front, think GOOD or BAD, flip, grade
  yourself. No custom tap template.
- [x] Success criterion? → Daily habit: reviewed on the phone daily for a week without
  friction.
- [ ] Which GitHub owner? The user will create an organization for everything Anki-related;
  the repo goes there. Its name isn't known yet.

## Risks and unknowns

- Who decides the "right" answer for borderline items, and on what source, so labels stay
  accurate (see the policy limits above).
