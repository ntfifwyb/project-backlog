# Real World Ores

## Summary *

A Minecraft mod whose goal is to add every ore from real life: every listed mineral
(the IMA list, roughly 6,000), each generating where it forms in reality, and smelting
into its product when it is smelted in real life.

## Problem *

Vanilla Minecraft has only a handful of ores (coal, iron, copper, gold, redstone, lapis,
diamond, emerald, quartz, ancient debris); real-world ores are far more numerous.

## Users and context

- Minecraft players.

## Success criteria *

- [ ] Every IMA-listed mineral has a generation rule and generates somewhere in a large
  enough world, in its real host setting (rock type, depth, biome, or dimension), provable
  by a world scan or locate command.
- [ ] Each mineral's break difficulty follows its real Mohs hardness, and the hardest ones
  can only be mined with an upgraded drill.

## Scope *

### Must (MVP)

- Every listed mineral (IMA list, ~6,000) as an ore block in the game.
- Each ore drops an item when mined.
- Ores that are smelted in real life smelt into their product; others don't smelt.
- World generation follows realistic geology: ores appear where they form in reality
  (veins, host rock, depth, biome), roughly.
- Rarity is truly realistic: real abundance, so very rare minerals may need a large world.
- Minerals from meteorites, the Moon or other non-Earth settings generate by analogy in
  meteorite structures or the Nether/End.
- Mining difficulty from real Mohs hardness, plus an upgradable drill whose tiers are needed
  for harder ores (the only tech item in the first release).

### Later

- Publishing (where, licence): decided later.

### Not doing

- A tech tree (alloys, tools, armor, machines) in the first release, beyond the drill.

## Constraints

- Development costs $0 (workspace rule).
- Anthropic policy verdict (2026-11-19): **allowed, with limits**. Mineral facts are not
  anyone's IP, but the mod must not copy Mojang's textures, code or other assets beyond
  what Mojang's terms allow (AUP: no infringing third-party IP). Mineral data written with
  Claude's help must be checked, since outputs can be wrong.

## Decided

- Name: Real World Ores (`real-world-ores`).
- Platform: Minecraft Java, on whichever edition/version/loader is the most future-proof;
  judge that when the project starts.
- Scope of "every ore": every listed mineral (IMA list).
- Gameplay: block, drop, and smelting only where the mineral is smelted in real life.
- Generation: realistic geology.
- Textures: generated by a script from each mineral's real data (color, luster) on an
  original template; no hand drawing.
- Mineral data: Mindat plus the IMA list.
- Release: private for now (built and played locally); publishing decided later.
- Hardness: Mohs-based, with an upgradable drill in the MVP.
- Rarity: truly realistic; findability means "generates somewhere", not "in every world".
- Off-Earth minerals: mapped to meteorite structures and other dimensions.

## Risks and unknowns

- Mojang's EULA and usage guidelines govern mods (no Mojang assets redistributed, rules
  on monetization): a third-party rule, for the user to decide on.
- ~6,000 minerals each need a texture, data and a generation rule: hand work is
  impossible at that size, so textures and data must be generated from a mineral database.
- Mindat's data licence and API terms limit what can be bundled; check before relying on
  it. Wikidata (CC0) is the fallback.
- Registering ~6,000 blocks and items may strain load time and memory; measure early.

## First session

- The data pipeline: a script that builds the mineral dataset (IMA list, color, luster,
  Mohs hardness, host setting, whether smelted) from Mindat + IMA, and generates a few of
  the ore blocks in-game from it.
